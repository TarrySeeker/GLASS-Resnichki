# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Next.js 16.2.12 (App Router) + React 19.2.4 + Tailwind CSS 4 — решение пользователя,
подтверждено в интервью: «Новый Next-проект в projects/resnichki». Совпадает с соседними
приложениями репозитория (`projects/auto-electronics`, `projects/gym-flash`).
Деплой-таргет не назван.

## Users

Первичная аудитория — женщина, которая ищет мастера по наращиванию ресниц и **выбирает не
по цене**. Ситуация: она уже видела десятки одинаковых аккаунтов и сайтов lash-мастеров и
не может отличить их друг от друга. Задача, которую она выполняет: понять за несколько
секунд, что этот мастер — другого уровня, и решиться написать.

Модель бизнеса подтверждена пользователем: **студия с командой мастеров**. Интонация сайта —
«мы», бренд стоит выше отдельной личности. Вместо экрана одного мастера — экран команды.
Поимённого состава нет, имена мастеров остаются заглушками.

## Product Purpose

Имиджевый сайт lash-бренда. Цель — не продать услугу со страницы, а изменить категорию,
в которой посетительница держит этого мастера: не «ещё один beauty-аккаунт», а бренд.
Успех = посетительница доходит до формы записи и отправляет её.

## Positioning

Заявленная позиция: работа поштучно, с разметкой формы под лицо до начала работы, и единый
стандарт этой работы у всех мастеров студии. Ни одна из этих вещей не проверяема со стороны —
поэтому сайт не заявляет её словами, а показывает темпом, масштабом и сдержанностью самой
страницы. Для студии это ещё и главный риск позиционирования: команда обычно читается как
«поток», и сайт обязан работать против этого чтения.

## Operating Context

Посетительница приходит с телефона, чаще всего из соцсети, в разглядывающем режиме, а не в
поисковом. Значит: мобильная версия — основная сцена, а не адаптация десктопа; первый экран
работает без прокрутки и без объяснений; целевое действие должно быть достижимо с любой точки
страницы.

## Capabilities and Constraints

- Одностраничный имиджевый сайт. **E-commerce отсутствует намеренно** — каталога, корзины,
  чекаута и личного кабинета нет. Это решение пользователя: первая половина
  `CLAUDE.md` описывает интернет-магазин, и эта часть брифа снята.
- **Двуязычность RU/EN** — подтверждена в интервью. Полный переключатель языка, оба набора
  текстов. Шрифтовая пара обязана нести кириллицу и латиницу в одном оптическом характере.
- Форма записи без бэкенда: обработчик отправки не подтверждён, поле для него оставляется
  явной дырой.
- Открытых продуктовых решений не осталось.

## Brand Commitments

Имени бренда не существует — пользователь подтвердил «всё заглушки». Рабочее имя вводится
как опора для типографики и логотипа и помечается как заменяемое.

**Планка ремесла, зафиксированная пользователем:** Aesop, Byredo, The Row. Уровень
исполнения этих трёх — проходной балл сборки, а не источник вдохновения. Измеримые
требования — в `docs/quality-bar.md`.

**Выбранное направление:** пользователь взял стандарт категории («то, что делают все,
исполненное безупречно») вместо предложенных авторских миров. Это стоячее предпочтение:
конвенция становится обязательством, исполняется в полную силу и без протащенных
странностей. Планка выше отменяет привычное для категории решение «тёмный фон плюс
макро-глаз»: у Aesop, Byredo и The Row интерфейс почти невидим.

Обязательные ограничения интонации заданы брифом и являются связывающими:
запрещены розовый + белый + золото, золотые градиенты, скрипт-шрифты в заголовках,
ресницы как декоративные иконки, слова PREMIUM / LUXURY / BEST / №1 / EXCLUSIVE,
шаблонные fade-up из библиотек, стоковая beauty-съёмка.

## Evidence on Hand

**Ничего реального нет, и ничто из этого не выдумывается:**
- фотографий нет — все изображения заменяются арт-заглушками с подписью сюжета;
- цен нет — ни одной суммы на сайте;
- отзывов нет — секции отзывов на сайте нет вообще;
- цифр нет — ни стажа, ни числа клиентов, ни процентов;
- контактов, адреса, города и имени мастера нет — явные дыры вида `— ГОРОД —`.

Есть разбор семи сайтов-референсов с фактическими значениями:
`docs/reference-analysis.md`, скриншоты — `references/`.
Есть памятка по особенностям Next 16: `docs/next16-notes.md`.

## Product Principles

1. **Сначала уровень, потом тема.** Сначала посетительница должна понять «это дорогой бренд»
   и только потом — «это про ресницы». Порядок обратный привычному для категории.
2. **Пустота — доказательство.** Мастер с потоком клиентов не может позволить себе пустую
   страницу. Незаполненность работает как утверждение о загрузке и отборе.
3. **Не заявлять то, что можно показать.** Любое утверждение о качестве, которое нельзя
   подтвердить, вырезается и переводится в поведение интерфейса.
4. **Дыры остаются дырами.** Отсутствующие данные видны как отсутствующие. Правдоподобная
   выдумка на месте заглушки — дефект, а не черновик.
5. **Мобильная версия — оригинал.** Решения для 390 принимаются отдельно, а не выводятся
   сжатием десктопа.

## Accessibility & Inclusion

Требование задано брифом: контраст WCAG AA, полная клавиатурная навигация, семантическая
разметка, настоящие метатеги. Плюс — из-за объёма движения — обязательная поддержка
`prefers-reduced-motion`.
